# 비평가 지침

만든 영상을 판정하는 법이다. 원칙 다섯 가지:
1. 비평가는 만든 쪽과 **다른** 에이전트다. 만든 기록을 보지 않는다.
2. 잴 수 있는 것은 **합격·불합격 관문**으로 본다(1장).
3. 품질은 **기준 그림과 맞대기**로 본다(낫다 / 같다 / 못하다). 짝은 스토리보드가 정한다(3장).
4. 흔들리기 쉬운 항목은 **측정값이 점수 상한**을 정한다(4장).
5. 한 판정은 비평가 **2~3명 패널**의 항목별 중앙값이다. **채점 예시**로 눈금을 맞춘다(5·8장).

## 0. 비평가에게 주는 것과 주지 않는 것
- **준다**(모두 작업 폴더 안):
  - 결과 영상 `out/final.mp4`
  - 스토리보드 `storyboard/shots.json` — 샷마다 `shot_type`·`anchor`(기준 그림 id), 일부러 가장자리를 넘는 샷은 `bleed: true`
  - 효과음 계획 `audio/events.json` — G3·Q8용 설계 자료(자기 평가가 아님). 사건마다 `tier`
  - 고른 예시의 대표 프레임 `example/keyframes/`
  - 기준 그림 `review/refs/`(+ 목록 `anchors.json`), 채점 예시 `review/refs/exemplars/`(+ `exemplars.json`)
  - 측정 도구 `critic/tools/`와 이 문서. 규칙 이름(A1, T1, R9 …)의 뜻은 `references/rules.md`에서 찾아본다.
- **주지 않는다**: 만든 쪽의 진행 기록·README·자기 채점·변명, `review/type_spec.md`, 다른 비평가의 결과. 비평가는 처음 보는 사람처럼 본다.
- 비평가는 고치지 않는다. 판정과 '고칠 것'만 낸다.
- 정직: 점수를 맞추려고 기준을 바꾸지 않는다. 판단이 애매하면 낮은 쪽을 고르고 이유를 적는다.

측정은 먼저 한 번에 돌린다(도구는 이 스킬 폴더 기준 경로, 결과는 자기 폴더에):
```bash
python3 -I <이 스킬>/critic/tools/measure_motion.py out/final.mp4 --out review/critic_A/measure \
    --shots storyboard/shots.json --events audio/events.json --all
python3 -I <이 스킬>/texture/measure_texture.py out/final.mp4 --frames <샷별 키 프레임> \
    --shots storyboard/shots.json --json review/critic_A/texture.json
```
도구는 숫자와 그림만 낸다. 판정은 비평가가 한다.

## 1. 관문 (하나라도 불합격이면 통과 못 함)

| # | 관문 | 합격 기준 | 도구 |
|---|---|---|---|
| G1 | 첫 움직임 | 0.15초 안에 화면이 움직이고, 0.7초 안에 첫 글자·주인공 | `--pace`(`first_move_s`. 첫 글자·주인공인지는 눈으로) |

| G3 | 소리 싱크 | 효과음의 80% 이상이 화면 사건과 ±1프레임 | `--sync`(`audio_on_visual_within_1frame` — 우연 값 `chance_*`보다 충분히 높아야 근거) |

## 3. 기준 그림과 맞대기 (가장 중요)

### 기준 그림 받기
기준 그림은 KAX MCP가 준다. 보통 만든 쪽이 스토리보드 때 받아 둔다. `pair_board.py`·`panel.py`(와 짝 빈 면을 재는 `measure_motion.py --contact`·`texture/measure_texture.py`)는 기준 그림 폴더에 **그림 파일 + `anchors.json`**이 있어야 돈다.
- 유형마다 쓸 수 있는 id: `get_shot_types(names)` → `anchor_ids`.
- 그림 받기: `get_critic_refs({ids: [...]})` 또는 `get_critic_refs({types: [...], per_type: 2})`. 한 번에 그림 8장(기준 그림 + 채점 판)까지라 나눠 부른다.
- **id 꼴**: `<유형>_<예시 id>_f<프레임>` — 11유형 중 하나 + 그 그림을 뽑은 공개 예시 id + 프레임 번호. 예: `chat_input_ex-102_f128`.
- 받은 칸(`structuredContent.anchors[]`): `id`, `type`·`type_desc`(유형과 제목), `source_example`·`shot`·`frame`(어디서 뽑았나), `aspect`, `q`(이 그림이 기준이 되는 항목), `why`(왜 기준인가), `motion`(움직임 메모), `image`(그림 자리).
- **저장하는 꼴**(도구가 이 꼴을 읽는다):
  1. 그림: 결과 안에 `anchors[]` 차례대로 온다(그 뒤 채점 판). k번째로 온 그림 = `content_index` 오름차순으로 늘어놓은 k번째 항목 — 클라이언트가 글 항목을 빼면 `content_index` 값은 받은 자리와 어긋나니 값이 아니라 차례로 짝짓는다. Claude Code는 그림마다 `[Image: source: <경로>]` 줄을 붙이고 받은 webp를 그 경로에 그대로 저장한다 → 그 파일을 `review/refs/<id>.webp`로 복사하고 크기가 `image.bytes`와 같은지 본다. 그림 본문(base64 `data`)을 직접 받으면 풀어서 같은 이름으로 쓴다.
  2. 목록 `review/refs/anchors.json`:
     ```json
     {"types": {"chat_input": {"desc": "채팅·입력창·UI 조작(커서·버튼·말풍선)", "count": 2}},
      "anchors": [{"id": "chat_input_ex-102_f128", "type": "chat_input", "type_desc": "채팅·입력창·UI 조작(커서·버튼·말풍선)",
                   "q": ["Q1", "Q4"], "why": "…", "motion": "…", "file": "chat_input_ex-102_f128.webp"}]}
     ```
     **직접 적지 않는다**: 결과의 목록 조각 리소스(`review/refs/parts/anchors-<키>.json`)를 `python3 -I <이 스킬>/scripts/mcp_files.py place`로 놓고 `python3 -I <이 스킬>/scripts/mcp_files.py refs`를 한 번 돌리면 이 꼴로 쓴다(받은 `anchors` 칸 + 그림 파일 이름 `file`, `types`는 유형마다 제목 `desc`와 그림 수 `count`). 나눠 받았으면 받을 때마다 place → refs(같은 id는 하나로 합침). refs는 그림 크기·sha256을 확인하고, 틀린 그림은 목록에서 빼고 끝 코드 1로 알린다. 조각 리소스를 못 받는 클라이언트(`inline: true`)면 받은 칸으로 이 꼴을 직접 쓴다.
- 자리: 도구 기본 경로는 스킬 뿌리 `kax_paths.json`이 정한다 — 작업 폴더 기준 `review/refs/`(기준 그림), `review/refs/exemplars/`(채점 예시, 8장). 다른 자리면 인자로 준다(`pair_board.py --anchors`, `exemplar_board.py --spec`).
- 받은 자료는 그 작업 폴더에만 둔다.

### 짝은 스토리보드가 정한다
- 맞대기 짝은 `shots.json` 샷마다의 `anchor`다(규칙 D1). 비평가가 바꾸지 않는다.
- `anchor`가 없거나 `anchors.json`에 없는 id인 샷은 **맞대기 '못하다'**로 친다(짝 없이 새로 짠 샷).
- 더 맞는 짝이 있다고 보면 `other_notes`에 적기만 한다.

### 판 만들기
```bash
python3 -I <이 스킬>/critic/tools/pair_board.py --list                     # 받은 기준 그림 id·유형·Q·이유
python3 -I <이 스킬>/critic/tools/pair_board.py out/final.mp4 --out review/critic_A/pairs \
    --shots storyboard/shots.json --pair 96=chat_input_ex-102_f128 --pair 200=calendar_data_ex-105_f230 \
    --phone --sheet --scale
```
- 같은 높이(`--height`, 기본 540)로 왼쪽 결과·오른쪽 기준을 붙인다. `--phone` = 폭 360px 사본 줄, `--sheet` = 모든 판을 이은 `pairs_sheet.png`, `--scale` = 화면 높이 15%·40% 안내선 + 주인공 높이(추정)와 높이 비(`scale.json`).
- `--frame <f> --type <유형>`이면 그 프레임을 그 유형 기준 그림 전부와 붙인다.
- 정지 한 장끼리의 비교다. 움직임 곡선(Q3)·움직이는 디테일(Q4)은 영상과 `--entries` 값을 함께 본다.

### 판정
- 샷마다 **낫다 / 같다 / 못하다** 하나 + 이유 한 줄. 샷 대표 프레임(`key`)과 짝을 같은 크기로 놓고 본다.
- 주인공이 짝보다 많이 작으면(높이 비 0.7 아래, 규칙 R11) '못하다'가 나오기 쉽다. 높이 비는 추정이라 눈으로도 보고 근거로 적는다.
- 맞대기 통과 조건은 6장.

## 4. 측정 상한
측정값이 조건을 못 채우면 그 항목은 **상한 점수를 넘을 수 없다.** 조건을 채우면 2장 기준 문장대로 눈으로 매긴다.

| 항목 | 조건 (8점 이상이 되려면) | 못 채우면 | 도구 |
|---|---|---|---|
| Q1 밀도·층 | 샷마다 바탕 결 세기가 그 바탕 유형 범위 안(`texture/ranges.json`, 격자 바탕은 그레인 몫 `tex_p50` — R6). 빈 면이 짝보다 **10%p 넘게 더 비지 않음**(`empty_diff_vs_anchor` ≤ +0.10, +면 더 빔 — R1). 더 찬 쪽(−)은 숫자 상한이 없다 — 눈으로: 주인공 시선 하나, 겹친 층 3겹 안(작은 디테일은 따로), 중간 층이 주인공 글자 획을 가리지 않음. 평평하게 둔 카드·UI 판의 안쪽은 내용으로 친다 | 결 범위 밖이거나 10%p 넘게 더 빈 샷이 전체의 25%를 넘으면 상한 7. 더 찬 샷이 어수선하면(시선 둘 이상, 층 4겹 이상, 중간 층이 글자를 가림) 상한 없이 눈으로 깎고 `why`에 근거 프레임을 적는다 | `measure_texture.py --shots`, `--contact` |
| Q2 타이포 | 화면마다 강조 정확히 1개(로고 한 낱말 화면은 예외, T1) · 문장 한 줄 또는 격자 칸 하나 안 처리 2가지 이하(T2) · 돌출 그림자 0(T1) · 키네틱 주인공:곁 ≥ 3.5, UI 제목:본문 ≥ 2.2, 한 화면 크기 단계 ≤ 3(T3) · 글자끼리 겹침 0 · 데이터 UI 화면(달력·표·대시보드)은 축 머리·보조 28px 이상이거나 없음, 칸 제목:보조 ≥ 2.2, 상태 표시(오늘·선택)는 채우지 않은 테두리·밑줄·무채색·같은 굵기면 강조로 세지 않음 — 채운 원·강조색·더 굵게는 강조(R9) · 한글 자간에 + 없음(R10) | 겹침 → 상한 6. 그 밖에 하나라도 못 채운 샷이 있으면 → 상한 7 | 눈 + 근거 프레임(+ `--text`. 한글 자모 조각으로 쪼개진 줄은 직접 잰다) |
| Q3 움직임 곡선 | 끝 카드 밖에서 1초 넘는 완전 정지 0(E7). 끝 카드의 아주 느린 흐름은 정지가 아니다(R5) — 끝 카드 처음·끝 프레임을 나란히 놓고 흐름이 보이는지만 본다 | 있으면 상한 7 | `--pace`(`static_longest_s`·`static_runs_s`) |
| Q4 디테일 | 디테일 6종(2장 Q4 줄) 중 **4종 이상을 근거 프레임과 함께** 적음, 시그니처 샷에 3종 이상 | 3종 → 상한 7, 2종 이하 → 상한 6 | 눈 + 근거 프레임 |
| Q5 구성·시선 | 주요 글자·주인공이 가장자리에서 짧은 변의 **5% 이상** 떨어짐(E3). 예외: 전환 중 6프레임 이하, `bleed: true` 샷의 의도한 넘침(화면보다 큰 글자, 줌 통과, 밀어 들어가는 화면) | 예외가 아닌데 어긴 구간(라벨·작은 글자가 밀려 잘림 등) → 상한 7 | `--margins`(`margin_violations`, bleed 샷은 `margin_violations_excused`) + 근거 그림 |
| Q6 시그니처 | 시그니처 샷 맞대기가 본인 판정으로 '같다' 이상 | '못하다' → 상한 7 | 맞대기 판 |
| Q8 소리 | ① 효과음 음색 **4종 이상** ② 시그니처·첫 사건이 일반 사건보다 **+4dB 이상** ③ 효과음이 바로 앞 바탕보다 **+8dB 이상**인 사건 80% 이상 ④ detail 사건 크기 중앙값이 normal보다 **2dB 이상 작음**(detail이나 normal이 없으면 해당 없음) — 규칙 E2·R12 | 하나·둘 못 채우면 상한 7, 셋 이상 못 채우면 상한 6. ①~④를 함께 센 상한 후보는 `--sfx`의 `q8_v06.cap` | `--sfx`(`tier_order`, 큰 착지 바로 뒤 작은 사건은 앞 소리를 같이 읽으므로 `louder_details`·`alone`도 본다) |

- `--sfx`는 사건 등급을 효과음 계획의 `tier`(signature / first / normal / detail)로 읽는다.
- 상한은 내려가기만 한다. 측정이 좋다고 점수를 올려 주지 않는다.
- 도구가 틀렸다고 보면(예: 도형을 글자로 잡음) 근거 프레임을 붙여 `other_notes`에 적고, 그 값을 뺀 뒤 판단한다.

## 5. 패널 (비평가 2~3명)
1. 지휘하는 쪽(만든 세션)이 비평가 A·B를 **동시에** 띄운다. 비평가끼리는 서로의 결과를 보지 않는다. 각자 `review/critic_A/`, `review/critic_B/`에 7장 양식으로 낸다.
2. 묶기:
   ```bash
   python3 -I <이 스킬>/critic/tools/panel.py review/critic_A review/critic_B --out review/panel --shots storyboard/shots.json
   ```
   → `panel.json`·`panel.md`: 항목별 점수 표·중앙값·중앙값 평균, 관문 합침, 맞대기 다수결, 통과 여부와 이유, 3번째 필요 여부(`need_third`), 고칠 것 후보. `cap`을 넘는 점수는 `cap`으로 읽고 표시한다.
3. **3번째 비평가 C**는 `need_third: true`일 때 띄운다. 앞 두 명으로 보는 조건:
   - 어떤 항목이든 A·B가 **2점 이상** 차이
   - A·B의 통과 여부가 다름
   - 두 명 평균(항목 평균의 평균)이 **경계 띠 7.75~8.25** 안
   - 맞대기에서 한 명만 '못하다'를 낸 샷이 시그니처·첫 샷·끝 샷
   - G2·G4에서 갈림

   조건이 걸려도 3번째가 어떤 점수를 줘도 결과가 같으면 `need_third: false`다(이유는 `need_third_why`).
4. C까지 매기면 `panel.py review/critic_A review/critic_B review/critic_C --out review/panel …`로 다시 묶는다. 최종 = 항목별 **중앙값**.
- 판정 한 번 = 비평가 2~3명. 판정은 최대 3번이다(비평가 최대 9명). 시간 예산 60~120분(규칙 A6).

## 6. 통과 조건과 고칠 것
- **관문**: G1~G5 모두 합격.
- **품질**: 항목별 중앙값이 모두 7 이상, 중앙값의 평균 8.0 이상.
- **맞대기**: 같은 샷에 **2명 이상**이 '못하다'일 때만 그 샷은 '못하다'. '같다' 이상인 샷이 80% 이상이고, 시그니처·첫 샷·끝 샷에 '못하다'가 없다.
- **고칠 것 3개**: 비평가들의 '고칠 것' 가운데 **2명 이상이 짚은 것**을 먼저, 그다음 중앙값이 가장 낮은 항목 순서로. `panel.py`가 항목(Q·G 번호)별로 후보를 모은다. 같은 항목이라도 다른 문제를 짚었을 수 있으니, 글을 읽고 묶는 것은 지휘하는 쪽이 한다.
- 통과하지 못하면 고칠 것 3개를 고치고 다시 판정한다. 통과하거나 3번째 판정에서 멈추고 남은 문제를 보고한다.
- 지휘하는 쪽은 다음 판정을 띄우기 전에 `critic/tools/fix_gate.py check review/fix_r<n>/고칠것.md`의 끝 코드 0을 확인한다. 비평가는 다음 판정에서 그 표의 '확인됨' 줄을 그 프레임에서 먼저 본다(판정에는 표가 아니라 영상만 쓴다).
- 효과음 사건 프레임은 소리의 머리(가장 먼저 크게 들리는 자리)다. 뒤가 커지는 라이저는 사건으로 세지 않는다(`references/sound.md` 1장).

## 7. 비평가 한 명의 출력 (`critic.json`, 키 고정)
```json
{
  "critic_version": "0.3",
  "critic_id": "A",
  "video": "out/final.mp4",
  "gates": {"G1": {"pass": true, "value": "..."}, "G2": {"pass": true, "value": "..."}, "G3": {}, "G4": {}, "G5": {}},
  "quality": {"Q1": {"score": 8, "cap": null, "frames": [12, 96], "why": "..."}, "Q2": {}, "Q3": {}, "Q4": {}, "Q5": {}, "Q6": {}, "Q7": {}, "Q8": {}},
  "pairs": [{"shot": 1, "anchor": "logo_title_ex-101_f030", "frame": 22, "verdict": "같다", "why": "..."}],
  "signature_shot": 4,
  "fixes": [{"item": "Q2", "what": "...", "how": "..."}],
  "other_notes": ["..."]
}
```
- `gates`·`quality`의 빈 칸은 위 G1·Q1과 같은 꼴로 채운다.
- `video`: 판정한 영상. 작업 폴더 기준 경로 그대로(`out/final.mp4`) 적는다. `panel.py`가 비평 폴더(`review/critic_A`, `review/round2/critic_A` …)에서 위로 올라가 그 영상이 있는 작업 폴더를 찾아, 비평가들이 같은 작품을 봤는지 맞춰 본다. 비평 폴더가 작업 폴더 밖에 있으면 절대 경로로 적는다.
- `cap`: 4장 상한이 걸렸으면 그 숫자, 아니면 `null`. `score`는 `cap`을 넘지 않는다.
- `verdict`는 `낫다`·`같다`·`못하다` 셋 중 하나.
- 함께 낸다: `critic.md`(요약 + **고칠 것 3개** — 가장 낮은 항목부터 '무엇을 어떻게'), `pairs/`(맞대기 판).

## 8. 채점 예시 (눈금 맞추기)
- 받기: `get_critic_refs({include_exemplars: true, …})` 또는 `get_critic_refs({exemplar_ids: [...]})`. 그림 8장 한도에 판도 세므로, 못 실은 판은 `board: null`로 온다 → `exemplar_ids`로 다시 받는다.
- 받는 차례(판 13장, 그림 8장 한도): 기준 그림(`ids`·`types`)을 받는 호출에 `include_exemplars`를 섞지 않는다. 기준 그림이 그림 칸을 먼저 써서 판이 4장만 온다. 판은 `get_critic_refs({include_exemplars: true})`(목록 13개 + 판 8장) → `mcp_files.py refs` → 알린 '판을 아직 못 받은 채점 예시' id를 `get_critic_refs({exemplar_ids: [...]})`로 받기 → 다시 `refs`. 알림이 없어질 때까지 한다(보통 두 번에 13장).
- 저장하는 꼴:
  - 판 그림: 기준 그림 뒤에 `exemplars[]` 차례대로 온다(`board`가 null인 예시는 건너뜀 — 짝짓기·저장은 3장 '저장하는 꼴' 1과 같음). 받은 webp를 `review/refs/exemplars/<id>.webp`로 복사만 한다.
  - 목록 `review/refs/exemplars/exemplars.json` = `{"exemplars": [받은 exemplars 칸 그대로, board만 "<id>.png"]}` — 목록 조각 리소스(`review/refs/parts/exemplars-<키>.json`)를 place로 놓고 `mcp_files.py refs`를 돌리면 판 PNG와 함께 이 꼴로 쓴다. 판을 아직 못 받은 예시는 board null로 적고 id를 알려 주니, 그 id를 `exemplar_ids`로 다시 받아 다시 refs.
- 예시 하나에 든 것: 요청 한 줄, 비평가 수와 점수 근거(`score_basis` — 여러 명이면 중앙값, 한 명이면 그 점수), Q1~Q8 점수와 평균, 관문, 맞대기(같다 이상 샷 수), 판정과 이유, 공통 메모(2명 이상이 짚은 것), 시그니처 샷, 판 그림(샷마다 대표 프레임 한 장 — ★ 시그니처, 빨강 = 맞대기 '못하다' — 아래에 점수 줄과 공통 지적).
- 비평가는 **매기기 전에** 예시 판을 본다. 자기 점수가 예시와 다르면 왜 다른지 한 줄씩 `other_notes`에 적는다.
- 예시에 들어간 영상을 다시 매길 때는 그 예시를 빼고 준다.
- 판을 새로 그리는 도구는 `critic/tools/exemplar_board.py`(판정 폴더에서 점수를 읽어 판을 그린다).
