# 바탕 결 쓰는 법

A1 ①(바탕 결)을 지키는 법이다. 규칙 한 줄: `texture/texture.js`로 바탕 유형에 맞는 결을 깔고, 렌더 뒤 잰 `tex`(원본)·`tex360`(폰)이 2장 범위 안, 정지 구간 flick ≤ 0.15. 비네트·번쩍이는 그레인은 쓰지 않는다(5장). 격자가 있는 바탕은 R6.

| 파일 | 하는 일 |
|---|---|
| `texture/texture.js` | 결 만들기 — `KMTex.create` |
| `texture/measure_texture.py` | 결 세기·폰 잔존·빈 면·깜빡임 재기 |
| `texture/ranges.json` | 바탕 유형별 목표 범위 |
| `texture/calibration.json` | 세기 → 측정값 보정 기록 |

## 1. 만들기 — `texture/texture.js`
순수 JS 파일이다. 빌드·네트워크·`Math.random`·`Date`를 쓰지 않는다. 같은 시드 + 같은 시각 t = 같은 그림. 작업 폴더에 복사해 `<script src="texture.js">`로 넣는다.

```js
const bg = KMTex.create(document.getElementById("bgwrap"), {   // 캔버스 하나를 부모 맨 뒤에 붙인다
  width: 1920, height: 1080, base: "#f3efe8", seed: 7,
  layers: [
    { kind: "cloth", tex: 2.2 },                  // 천 결
    { kind: "grain", tex: 0.9 },                  // 미세 그레인(폰에서 남는 몫)
    { kind: "glow",  span: 6, x: 0.78, y: 0.18 }, // 부드러운 빛 번짐(빛만 더함)
  ],
  flow: 6,      // 큰 결(얼룩·주름)·빛이 흐르는 속도 px/초. 고운 결은 정지
});
bg.render(t);   // 프레임마다, t = 초
```

붙이는 곳(첫 인자를 `null`로 주면 화면에 붙이지 않고 캔버스만 만든다 — `bg.canvas`):
- km 엔진: `KM.add({ id: "bg", f0: 0, f1: N, build(el) { bg = KMTex.create(el, …) }, render(f) { bg.render(f / FPS) } })`
- kx 엔진(캔버스 하나): `bg = KMTex.create(null, …)` 뒤 `KX.under = (c, F) => { bg.render(F / FPS); c.drawImage(bg.canvas, 0, 0); }` — 장면 맨 밑에 깐다.
- 부품 + HyperFrames(`KC.toHF`): `KC.toHF(부품들, root, { duration, under: (ctx, f) => { bg.render(f / FPS); ctx.drawImage(bg.canvas, 0, 0); } })`.
- 엔진·부품 없이: 바탕 요소를 부모로 주고, 드라이버 트윈의 `onUpdate`에서 `bg.render(t)`.

| kind | 무엇 | 세기 | 다른 값 |
|---|---|---|---|
| `grain` | 미세 그레인(σ ≈ 0.8px) | `tex` / `tex360` / `amp` | `boil: 초` = 그 시간에 걸쳐 다른 그레인으로 천천히 바뀜(세기 유지) |
| `paper` | 짧은 섬유 + 그레인 + 옅은 얼룩 | 〃 | `fibers`(섬유 밀도 배수), `low`(얼룩 세기, 0 = 끔) |
| `cloth` | 씨실·날실(주기 `period` 5px) + 그레인 + 부드러운 주름 | 〃 | `period`, `low` |
| `grid` | 아주 옅은 격자·사선, 1px | `line` = 선 밝기 차(0~255) | `cell`, `width`, `hatch`(45° 사선 간격), `lines: "h" / "v" / "none"`, `sign` |
| `glow` | 부드러운 빛 번짐 | `span` = 가장 밝은 곳에 더하는 밝기 | `x`, `y`(0~1), `r`, `color`. 23초 주기로 0.04 폭만큼 아주 느리게 돈다 |

- **세기 정하기**: `tex`·`tex360`에 2장 목표값을 그대로 넣는다. 둘 다 주면 둘 다 넘는 쪽(큰 진폭)을 쓴다. `amp`는 진폭을 직접(밝기 표준편차, 0~255). 렌더 뒤 실제 값은 조금 다르니 **렌더 뒤 한 번 재서** 맞춘다(6장).
- 고운 결(grain·paper·cloth) 여러 개는 한 타일에 더해 그린다. 차례는 상관없다.
- **움직임**
  - 정지 화면의 '느린 흐름'은 큰 결과 빛이 맡는다(`flow`). 고운 결은 정지가 기본이다.
  - 카메라가 움직이는 장면은 `bg.offset(x, y)`를 프레임마다 넘겨 결을 화면과 같이 움직인다. 일정한 흐름이 필요할 때만 `drift: [vx, vy]`(px/초, 소수 자리)를 쓴다.
  - `subpixel: false`(정수 px 이동)는 쓰지 않는다. 1px마다 결이 통째로 튄다(flick 0.69).
- 사진 위에는 결을 얹지 않는다(사진이 이미 결이다). 사진 밖 여백이 단색일 때만 그 여백 유형으로 깐다.
- 결은 바탕에만 깐다. 카드·UI 판은 평평하게 둔다(그 안쪽은 R1에서 내용으로 친다).

## 2. 바탕 유형별 목표 범위
값은 `texture/ranges.json`에도 있다. 원본 = 긴 변 1280으로 줄여 잰 값, 폰 = 폭 360으로 줄여 잰 값. 범위 아래는 '결 없음', 위는 '잡음·가독성 위험'으로 본다.

| 바탕 유형 | 판별(잰 바탕색) | 목표 `tex`(원본) | 목표 `tex360`(폰) | `peak` 상한 |
|---|---|---|---|---|
| 밝은 종이·크림·흰 UI | 밝기 L ≥ 200, 채도 < 40 | **1.2 ~ 2.8** | **0.5 ~ 1.3** | 10 |
| 어두운 단색 | L ≤ 50 | **0.8 ~ 1.5** | **0.4 ~ 0.85** | 8 |
| 색면 | 그 밖 | **0.7 ~ 1.6** | **0.35 ~ 0.9** | 8 |
| 사진 위 | 바탕색 하나로 안 잡힘 | 얹지 않음 | — | — |
| 옅은 격자·사선(성긴 무늬) | 어떤 바탕 위든 | 선 밝기 차 `line`: 밝은 바탕 **6~12**, 어두운 바탕 **18~26**, 칸 96px 이상 | `peak360` **2 ~ 5** | 14 |

- 이 범위는 **결을 깔 때의 세기**다. 잘 만든 영상에도 평평한 바탕이 많다. '모든 샷에 결'(A1)은 그대로 두고, 깔 때 이 범위 안에 둔다.
- 결은 빈 면을 채우지 않는다. 결만 있는 칸도 `empty`에서는 빈 칸으로 센다(빈 면 규칙은 R1).
- **격자·사선이 있는 바탕**(R6): 결 세기 범위(위 표의 `tex`·`tex360`)는 **그레인 몫**으로 본다 — `tex_p50`(칸이 240px처럼 100px 조각보다 넉넉히 크면 선이 대부분의 조각에서 빠져 중앙값이 그레인 값이 된다) 또는 격자만 끈 같은 설정의 `tex`. 격자 선은 `peak`·`peak360`으로 따로 본다. 격자가 들어가면 `tex`가 1~1.3 오르므로 격자를 포함한 `tex`는 참고로만 적는다.
- 세로 영상(1080×1920)은 폰 사본이 덜 줄어 `tex360`이 가로보다 1.2~1.4배 크게 나온다. 세로에서는 `tex360` 상한을 0.2 올려 본다.

## 3. 추천 설정

|---|---|---|---|
| **밝은 크림 UI(추천)** — 따뜻한 오프화이트 천 결 | `base "#f3efe8"`, `cloth tex 2.2` + `grain tex 0.9` + `glow span 6 (0.78, 0.18)` | tex 2.38 · tex360 0.72 · flick 0.02 | 결이 은은히 남고 20px 글자도 그대로 |
| 밝은 바탕 — 다른 안(종이 섬유) | `paper tex 1.8, tex360 0.75` + `glow span 6` | tex 1.89 · tex360 0.87 · flick 0.03 | 2배 확대하면 섬유가 '머리카락'처럼 보일 수 있다. 캔버스 결이 필요하면 천 쪽이 낫다 |

## 4. 재기 — `texture/measure_texture.py`

```bash
python3 -I <이 스킬>/texture/measure_texture.py out/final.mp4 --frames 24,175,300 --json review/texture.json [--debug review/texture_mask]
python3 -I <이 스킬>/texture/measure_texture.py out/final.mp4 --temporal 60-150      # 깜빡임(flick)
python3 -I <이 스킬>/texture/measure_texture.py review/refs/<기준 그림 id>.webp         # 그림도 된다
python3 -I <이 스킬>/texture/measure_texture.py out/final.mp4 --frames 96 --shots storyboard/shots.json   # 짝 기준 그림과 빈 면 차
```
입력: 그림 여러 장 또는 영상 하나, `--frames`(쉼표) 또는 `--every`(초), `--temporal f0-f1`, `--debug`(마스크 그림: 빨강 = 글자·주인공, 파랑 = 바탕 아님), `--anchor <그림 또는 id>`·`--shots`(짝 그림 — `--anchor`가 먼저).

**정의**
- 밝기: Y = 0.2126 R + 0.7152 G + 0.0722 B. 영상은 bt709 tv 범위로 풀어 0~255로 쓴다. 긴 변 1280으로 상자 평균 축소한다.
- 고역: HP = Y − G₃(Y) (Gₛ = 표준편차 s px 가우시안 흐림).
- 글자·주인공: max_RGB |RGB − G₁₂(RGB)| > 30인 화소를 10px 넓힌 것.
- 바탕색: 가장자리 띠(짧은 변의 3%) RGB 중앙값. 바탕 영역: 글자·주인공이 아니고 max_RGB |G₈(RGB) − 바탕색| < 24인 화소. 바탕 영역이 화면 12% 미만이면 글자·주인공만 뺀 전체를 쓰고 `bg_mode=fallback`(사진 위)으로 둔다.
- **`tex`** = 바탕 화소 HP의 √평균(HP²) ← 주 숫자.
- **`tex_p50`** = 100×100 조각(바탕 60% 이상) HP 표준편차의 중앙값. 촘촘한 결이면 `tex`와 비슷하고, 성긴 격자·요소 둘레만 있으면 0에 가깝다.
- **`peak`** = 바탕 화소 |HP|의 99백분위(격자·사선 선의 밝기 차).
- **`span`** = 바탕 화소 G₈(Y)의 5~95백분위 폭(빛 번짐·그라데이션·주름의 큰 흐름 — 요소 그림자도 섞인다).
- **`tex360` / `tex360_p50` / `peak360`**: 폭 360 사본에서 같은 식. HP는 G₁, 조각은 28px, 바탕 영역은 원본 마스크를 줄여 3px 깎아 쓴다. **`keep360`** = tex360 ÷ tex.
- **flick**(`--temporal`) = RMS(HP_t − HP_t−1) ÷ (√2 · RMS(HP)), 바탕 화소. 0 = 결이 그대로, 1 = 프레임마다 새 그레인. 바탕 마스크는 프레임마다 다시 잡고, 이웃 두 프레임 중 어느 쪽에서든 글자·주인공인 화소는 뺀다.
- **`empty`** = 32px 칸 중 빈 칸 비율(글자·주인공 화소가 없고 G₃(Y)의 2~98백분위 폭이 16 미만). 짝을 주면 `anchor_empty`, `empty_diff_vs_anchor` = empty − 짝 empty(+ = 더 빔), `empty_side`(±0.10 밖이면 더 빔·더 참)도 낸다.

**절차 (샷마다 키 프레임 1장 + 정지 구간 1곳)**
1. `--frames <샷별 키 프레임>`으로 잰다. 바탕 유형은 `bg_mode`·`bg_luma`·`bg_rgb`로 2장 표에서 고른다.
2. 결을 깐 샷은 `tex`가 원본 범위, `tex360`이 폰 범위 안이어야 한다. `tex`가 범위 안인데 `tex_p50`이 0에 가까우면 결이 아니라 요소 둘레·성긴 선이 잡힌 것이다 → `--debug` 그림을 본다.
3. 격자·사선은 `peak`·`peak360`으로 본다. 격자 바탕의 결 세기는 `tex_p50`(그레인 몫)으로 본다.
4. 정지·느린 구간 하나에 `--temporal`을 걸어 **flick ≤ 0.15**, 0.5 넘는 튐이 없는지 본다.
5. 360px 사본(`critic/tools/measure_motion.py --contact`의 `phone360.png`)을 눈으로 보고 결이 보이는지, 글자 가장자리가 지저분하지 않은지 본다.

한계: 바탕 위 반투명 카드, 1px 테두리, 흐린 그림자는 글자로 잡히지 않아 결로 조금 섞인다. 평평한 바탕 + 카드 UI에서 `tex` 바닥값은 밝은 바탕 0.40, 어두운 바탕 0.61이다(`tex_p50`은 0). 결이 약할 때는 `tex_p50`을 같이 본다. 그라데이션이 큰 바탕은 바탕색 판별이 흔들린다.

## 5. 금지
1. **비네트**(화면 가장자리를 어둡게 두르기). 결이나 빛 번짐 대신 쓰지 않는다. `glow`는 빛을 더하기만 해서 어두운 테가 생기지 않는다.
2. **번쩍이는 그레인**: 그레인 그림을 프레임마다 바꾸기, flick 0.5를 넘는 튐. 그레인은 정지가 기본이고, 바꾸려면 `boil`(4초 이상)만 쓴다. 정수 px drift도 같은 결함이다.
3. **글자를 해치는 세기**: 밝은 바탕 tex 2.8 초과·peak 10 초과, 어두운 바탕 tex 1.5 초과·peak 8 초과. 격자 선은 어두운 바탕 `line` 26, 밝은 바탕 12를 넘기지 않는다. 격자 칸이 글자 획 굵기와 비슷한 크기(48px 이하)면 글자 위에서 무늬가 겹쳐 보인다 → 칸은 96px 이상.
4. 결을 사진·제품 위에 얹기, 카드·UI 안쪽에 바탕 결을 이어 깔기.
5. 결 하나로 '층'을 채웠다고 보기(A1).

## 6. 세기 → 측정값 보정
`KMTex.CAL`은 진폭 1(밝기 표준편차 1)당 측정값이다(1920×1080, crf 16, 밝은·어두운 바탕 평균). 기록은 `texture/calibration.json`.

| kind | tex / 진폭 | tex360 / 진폭 | 메모 |
|---|---|---|---|
| grain | 0.89 | 0.415 | 폰에서 가장 잘 남는다 |
| paper | 0.83 | 0.35 | |
| cloth | 0.865 | 0.19 | 씨실 주기 5px는 폰에서 거의 사라진다 → 폰 몫은 grain으로 보탠다 |
| grid(선 밝기 차 1당, 칸 48·1px) | 0.111 | 0.060 | 칸 120·1.5px: peak ≈ 0.52 × line, peak360 ≈ 0.19 × line |

목표 `tex`를 넣고 렌더(crf 16·글자 카드 있음)한 뒤 나온 값. 낮은 쪽은 인코딩 잡음·UI 테두리가 더해져 조금 높게, 높은 쪽은 인코딩이 깎아 조금 낮게 나온다.

| 넣은 값 | 밝은 바탕 paper | 어두운 바탕 grain(`tex_p50`) |
|---|---|---|
| tex 0.8 | — | 0.83 |
| tex 1.0 | 1.17 (360 0.61) | — |
| tex 1.1 | — | 1.04 (360 0.67) |
| tex 1.5 | grain 1.68 (360 0.85) | 1.33 (360 0.78) |
| tex 2.0 | 1.93 (360 0.90) · cloth 2.00 (360 0.60) | — |
| tex 2.8 | 2.43 (360 1.13) | — |

인코딩 뒤에도 남는가:
- 정지한 고운 결은 crf 16~18 어느 쪽이든 목표 범위 안에 남는다(crf 16 ↔ 18: 원본 −2~−10%, 폰 0~−3%). crf 18로 낼 때는 `tex`를 10% 높여 넣는다.
- 어두운 바탕(L 13~20)의 tex 0.8 그레인도 crf 18에서 0.78(`tex_p50`), 폰 0.61로 남는다.
- 깜빡임: 정지 결 + 흐르는 빛 0.02~0.03, `boil` 0.047, 소수 자리 drift 0.15(세기 −15% 출렁임), 정수 px drift 0.69(튐).
