# 품질 규칙

kax-motion으로 만드는 영상의 품질 규칙 전부다. 지금 유효한 뜻만 적었다.

- 규칙 이름(A1, C1, D1, E1, R1, T1 …)은 SKILL.md·부품 README·비평 문서가 그대로 쓴다. 이름 뒤 `(→ Q2)`는 그 규칙을 보는 비평 항목이다(`critic/critic.md` 2장).
- 묶음: **A** 품질 · **C** 틀 · **D** 짝·사실·소리 시각·끝 · **E** 잦은 약점 · **R** 잰 값으로 정한 것 · **T** 타이포 · **G4 금지 목록** · 끝에 **비평 전 스스로 점검**.
- 다른 규칙으로 바뀐 이름은 한 줄로 남기고 `→`로 지금 규칙을 가리킨다.
- 쓰는 법과 값 표는 따로 둔다: 한글 서체 키트 `references/typography.md`, 바탕 결 `references/texture.md`, 렌더 함정 `references/render.md`, 소리 만들기·마스터 `references/sound.md`.
- 크기 숫자는 가로 1920 화면 기준이다. 세로·정사각은 C3대로 환산한다.

## A. 품질

### A1. 밀도·층 (→ Q1)
- 모든 샷은 **3겹 + 디테일**이다.
  - ① 바탕 결(그레인, 부드러운 빛 번짐, 종이·천 결, 아주 옅은 격자)
  - ② 중간 층(흐린 보조 UI, 반복 도형, 뒤쪽 카드, 큰 글자 그림자)
  - ③ 주인공
  - ④ 작은 디테일(커서, 강조 빛, 라벨, 점·선)
- **바탕 결**은 `texture/texture.js`로 바탕 유형에 맞게 깐다. 렌더에서 잰 `tex`(원본)·`tex360`(폰)이 그 유형 범위 안이고, 정지 구간 flick ≤ 0.15다. 비네트·번쩍이는 그레인은 쓰지 않는다. 범위·금지·재는 법은 `references/texture.md`.
- 결은 ①일 뿐이다. 결만으로 ②중간 층·④디테일을 채웠다고 보지 않는다.
- 빈 면은 짝 기준 그림보다 10%p 넘게 더 비지 않는다(R1).
- 재료가 없으면 코드로 그린 그림으로 채운다: 앱 화면 목업(상태 줄·탭·목록·카드), 일정·메시지·알림 카드, 차트 조각, 직접 그린 선 아이콘, 추상 도형. 실사처럼 꾸미지 않는다. 맞는 공용 부품이 있으면 새로 짜지 말고 부품을 쓴다.
- 로고·글자 한 줄만 있는 화면은 1초를 넘기지 않는다(끝 카드 제외).

### A2. 시그니처 장면 (→ Q6)
- 편마다 **1개 이상**, 1초 이상.
- 후보: 유리 방울 전환, 3D 기기 회전 공개, 큰 글자 펀치 인 + 움직임 번짐, 화면을 가로지르는 빛, 카드 무리가 한 화면으로 모이는 줌 아웃.
- 스토리보드 관문에서 '이 영상의 하이라이트'로 사용자에게 따로 보여 준다.
- 시그니처 구간은 프레임 띠로 먼저 검사한다(E1).

### A3. 디테일 체크리스트 (→ Q4)
한 편에 **4종 이상**, 시그니처 샷에는 **3종 이상**.

| 디테일 | 기본값 |
|---|---|
| 움직임 번짐 | 프레임당 20px 넘게 움직이는 요소에. 엔진·부품 번짐으로(가운데 기준·계단 없이 — E5·R13). HyperFrames 자동 번짐(`data-motion-blur`)은 끈다(`references/render.md` 2장) |
| 따라오는 두 번째 움직임 | 라벨·그림자·하위 요소가 2~4프레임 늦게 같은 곡선 |
| 정지 중 느린 흐름 | 멈춘 화면도 크기 1.00→1.01 또는 0.5~2px/초 이동 |
| 누름 흔들림 | 누를 때 0.96배로 3~5프레임, 탄성으로 복귀 |
| 빛 지나감 | 히어로 요소 위로 0.4~0.6초 사선 하이라이트(E6·R4) |
| 넘침 정착 | 도착할 때 1~3% 넘쳤다가 정착(예시 프리셋 범위 안) |

### A4. 한글 타이포 (→ Q2)
강조·격자·크기 재기는 T1~T3. 키트 쓰는 법은 `references/typography.md`.

- **언어**: 사용자가 한국어로 요청했으면 화면 글자도 한국어다. 영어로 바꾸려면 스토리보드 관문에서 묻는다.
- **역할·서체 수**: 한 화면은 역할 2~3개(예: 제목 + 본문, 키네틱 + 세리프 강조). 한글 서체는 한 화면 2개, 한 영상 3개까지. 같은 서체의 굵기 차이는 한 서체로 센다. 역할과 짝은 `typography/pairs.json`의 9역할에서 고른다.
- **섞인 줄**: 한 줄에 한글과 라틴·숫자가 섞이면 `KTypo`로 그린다. 같은 font-size로 서체만 바꾸지 않는다. 짝마다 한글 배율이 0.91~1.10배로 다르다. '한글은 1.1배' 같은 눈대중 배율을 쓰지 않는다.
- **높이·기준선**: 한글 높이는 라틴 대문자의 1.19~1.23배, 한글 가운데는 대문자 가운데에 맞는 것이 정상이다. 한글 윗선이 대문자 윗선보다 조금 위로 나온다. 같은 높이로 깎으면 한글이 작고 가벼워 보인다.
- **자간**: 본문 0~−0.5%, UI 제목 −2.5%, 키네틱 −3~−4%, 세리프 제목 −3%. 한글 제목에 +자간(벌림)을 쓰지 않는다. +자간은 라틴 대문자 라벨에만(+4~+10%). 겹침을 자간으로 풀지 않는다(R10).
- **줄 간격**: 본문 1.45, UI 제목 1.16, 키네틱 쌓기 0.93~1.02(받침이 다음 줄에 닿지 않는 최소), 세리프 1.1.
- **회전 중심**: 글자 단위로 돌리거나 키울 때 중심은 한글 글자 상자 가운데다 = 펜 + (0.5 × advance, 기준선 위 0.35~0.38em). kx 엔진 기본(0.3em, −0.36em)은 라틴용이라 한글이 비뚤게 돈다 → `KTypo.patchD2`.
- **글자 단위 진폭**: R7(굵기 700 미만)·R10(700 이상).
- **크기 대비** — 재는 법과 통과선은 T3.

  | 짝 | 최소 | 권장 |
  |---|---|---|
  | UI 제목 : 본문 | 2.2 : 1 | 2.4~3 : 1 (예: 72px / 28px) |
  | 키네틱 주인공 낱말 : 곁 낱말(라벨) | 3.5 : 1 | 4~6 : 1 (예: 160px / 32px) |
  | 큰 숫자 : 단위 | 2 : 1 | 단위 = 숫자 × 0.5(`numeric_hero`가 저절로) |
  | 본문 : 캡션(날짜·출처) | 1.15 : 1 | 크기 대신 색을 한 단계 흐리게 |

  - 한 화면 글자 크기는 3단계까지. 비슷한 두 크기(예: 48px과 56px)를 같이 두지 않는다. 대비가 안 보이면 하나로 합친다.
- **금지**
  1. 썸네일형 한글: 둥글고 굵은 한글(Do Hyeon, Gasoek One 등) + 돌출 그림자·두꺼운 외곽선·단단한 드롭 그림자. 그림자는 흐린 부드러운 그림자(불투명 25% 이하, 흐림 0.15em 이상)만.
  2. 압축 라틴과 둥근·넓은 한글을 같은 크기로 한 줄에: Big Shoulders·Archivo wdth 80 미만 옆의 Do Hyeon·Gasoek One·Pretendard 넓은 한글(라틴이 한글의 절반 폭으로 보인다). 압축 라틴은 숫자·단독 낱말로만 쓴다. 한글과 같은 줄이면 `kinetic_condensed` 또는 `numeric_hero`(단위 작게).
  3. 한 화면에 한글 서체 3개 이상.
  4. 같은 font-size로 서체만 바꾸기(섞인 줄은 `KTypo`).
  5. 한글 제목 +자간, 한글 이탤릭·기울임 변형. 가짜 이탤릭은 획이 망가진다. 기울임 연출은 글자 단위 skew 0.1 이하로 아주 약하게.
  6. 세리프 2종을 한 화면에(Noto Serif KR과 Hahmlet을 함께 쓰지 않는다).
  7. 렌더 중 네트워크로 서체 받기, `fonts/` 밖의 출처 모를 서체.

### A5. 소리 (→ Q8)
- 사건 유형마다 음색을 나눈다: 누름(짧은 클릭), 등장(팝·틱), 이동(휙), 정착(부드러운 툭), 강조(빛·쉬머), 전환(상승음·임팩트).
- 크기 위계(믹스 기준): 시그니처·첫 사건 −6dB, 일반 사건 −12dB, 잔 디테일 −18dB. 짧은 잔향 하나로 같은 공간에 둔다. 잰 값의 조건은 E2·R12.
- 음악이 없으면 합성 바탕(패드·가벼운 비트)을 깔고 효과음을 위에 둔다. 바탕 크기는 R2. 사용자가 음악을 주면 그 박에 사건을 맞춘다.
- 만드는 법(합성 단서·덕킹·마스터)은 `references/sound.md`.

### A6. 다듬기 시간
- 비평을 통과할 때까지 고친다. 시간 예산 60~120분, 판정은 최대 3번(판정 한 번 = 비평가 2~3명 패널, `critic/critic.md`). 20분대에 멈추지 않는다.
- 비평가는 만든 쪽과 **다른** 에이전트다.

## C. 틀

### C1. 예시는 리듬·움직임의 틀
- 예시에서 가져오는 것: 샷 길이 분포, 스태거 간격, 긴장도 곡선, 전환 종류, 움직임 프리셋, 디자인 값.
- 가져오지 않는 것: 샷 목록 그대로, 문장 구성, 칸 수, 예시의 문구·그림.
- 샷 목록은 내용에서 새로 짠다: 전하려는 말 3~5개 → 말마다 맞는 샷 유형(`get_shot_types`의 11유형) → 샷 수 ≈ 길이 ÷ 예시 평균 샷 길이.

### C2. 지어낸 말 금지
- 화면의 모든 글은 요청에서 나오거나 스토리보드 관문에서 사용자가 고른 것이다. 빈칸을 채우려고 말을 만들지 않는다.
- 내용이 모자라면 칸·샷을 줄이거나 글 없는 시각 요소(아이콘·도형, 숫자 대신 막대)로 채운다.
- 관문에서 핵심 문구 후보를 2~3개씩 보여 주고 고르게 한다.

### C3. 최소 글자 크기 (예시 디자인 값보다 먼저)
- 주요 글자 대문자 높이 **28px 이상**, 보조 **20px 이상**. 장식·배경 글자는 예외. 격자 칸 라벨(T2)과 데이터 UI의 축 머리·보조(R9)는 28px 이상이거나 아예 뺀다.
- 높이는 코드의 font-size가 아니라 렌더 프레임에서 잰 대문자(한글은 글자) 높이다(T3).
- 세로·정사각 영상은 화면 폭을 1920으로 환산해 같은 기준으로 본다(`critic/tools/measure_motion.py --text`의 `cap_1920`). 폰 폭 360px에서 같은 크기로 보이는 값이다.
- 예시 값이 더 작으면 키운다. 키워서 넘치면 칸·줄 수를 줄인다.

## D. 짝·사실·소리 시각·끝

### D1. 샷마다 기준 그림 짝 (→ Q1·Q2·Q5, 맞대기)
- 스토리보드 `storyboard/shots.json`의 샷마다 `shot_type`(11유형)과 `anchor`(같은 유형의 기준 그림 id)를 적는다. `anchor`가 없거나 받은 목록에 없는 id인 샷은 비평 맞대기에서 '못하다'로 친다.
- 기준 그림은 `get_critic_refs`로 받아 작업 폴더 `review/refs/`에 둔다. id 꼴은 `<유형>_<예시 id>_f<프레임>`(예: `chat_input_ex-102_f128`). 받는 법은 `critic/critic.md` 3장.
- 짝의 밀도·글자 크기 대비·여백·층 수·주인공 크기(R11)를 맞춘다. 키프레임을 그린 뒤 `critic/tools/pair_board.py`로 나란히 놓고 먼저 스스로 본다.
- 짝은 샷 유형으로 정한다. 숫자를 맞추려고 짝을 바꾸지 않는다(R1).
- 왜: 예시를 거의 그대로 옮긴 샷은 기준 그림과 같은 급이 나오지만, 짝 없이 새로 짠 샷은 품질이 떨어지기 쉽다.

### D2. 사실은 요청에서만 (→ G4·Q7, C2를 넓힘)
- 화면에 보이는 제품 기능·연동·숫자는 요청에 있는 것만 쓴다. 가상 앱이라도 요청에 없는 기능(메일 연동, 초대 보내기 등)을 사실처럼 보여 주지 않는다. 더 보여 주고 싶으면 관문에서 묻는다.
- 요청의 핵심 동작은 화면에서 그 동작으로 보여야 한다(예: '말로 말하면' → 타이핑이 아니라 말소리 파형·받아쓰기).

### D3. 강조색은 하나 (→ Q2)
- 한 화면의 강조색은 1개 + 회색 단계. 여러 색 글자는 예시가 그렇게 한 샷에서만.

### D4. 소리는 렌더에서 잰 사건에 (→ G3·Q8)
- 효과음 시각은 계획 값이 아니라 **렌더 프레임에서 잰 사건 프레임**(글자 착지, 줄 넘김, 누름 바닥)에 맞춘다.
- 확인: `critic/tools/measure_motion.py --sync --events audio/events.json` → 80% 이상이 ±1프레임 안.
- 부품 사건은 `events()`의 `onset`·`land`를 쓴다(R12).
- 일정 간격 틱으로 목록을 덮지 않는다. 실제 줄 넘김마다 놓는다.

### D5. 끝에서 멈추지 않기 (→ Q3)
- 마지막 1초를 넘는 완전 정지 금지. 끝 카드는 아주 느린 흐름(크기 1.00→1.02, 빛 이동)과 맺는 소리 하나(R5).
- 끝 카드의 이름·로고는 부제보다 2.5배 이상 크게.
- 끝 카드는 같은 배치로 4초까지 둘 수 있다(R3).

### D6. 비평 루프 (→ `critic/critic.md` 패널로 바뀜)

## E. 잦은 약점

### E1. 시그니처 장면은 프레임 띠로 먼저 검사 (→ Q6)
- 시그니처 구간 전체를 **2프레임 간격 띠**로 뽑아 한 장씩 본다. 렌더 초안에서 뽑는다(`references/render.md` 5장). 비평 전에 만든 쪽이 직접 본다.
- 띠에 없어야 하는 것:
  - 글자끼리 겹침(사라지는 글자와 나타나는 글자가 같은 자리에 한 프레임이라도 겹침)
  - **있을 수 없는 값**(시각 '4:85', 날짜 '13월', 음수 개수) — 숫자 섞기·카운트업은 유효한 값만 지나가게
  - 날아가야 할 주인공이 그냥 사라지기(이동이 보여야 함)
  - 반쯤 그려진 프레임
- 숫자 섞기는 자리마다 유효 범위를 정해 둔다(시: 0~23, 분 십의 자리: 0~5).

### E2. 소리 위계는 잰 값으로 (→ Q8)
- 렌더 소리에서 잰다(`critic/tools/measure_motion.py --sfx --events audio/events.json`).
  - ① 효과음 음색 **4종 이상**
  - ② 시그니처·첫 사건이 일반 사건보다 **+4dB 이상**
  - ③ 효과음이 바로 앞 바탕보다 **+8dB 이상**인 사건 **80% 이상**
  - ④ 등급 순서(R12)
- 사건마다 효과음 계획에 `tier`(signature / first / normal / detail)를 적는다. 도구가 이 칸으로 등급을 읽는다.
- 바탕 덕킹·마스터는 R2. 마스터가 위계를 눌렀으면 마스터가 아니라 믹스를 고친다.

### E3. 가장자리 여백 (→ Q5)
- 주요 글자·주인공은 화면 짧은 변의 **5% 이상** 가장자리에서 떨어진다.
- 카메라가 다가가는 샷은 다가간 **끝 프레임 기준**으로 본다(위 라벨을 미리 빼거나 내린다).
- 확인: `critic/tools/measure_motion.py --margins`.
- 일부러 가장자리를 넘는 연출(화면보다 큰 글자, 줌 통과, 밀어 들어가는 화면)은 그 샷에 `bleed: true`를 적는다. 비평가는 그 샷의 넘침을 예외로 본다.
- 같은 배치가 3초 넘게 이어지지 않는다. 다음 샷은 배치를 바꾼다. 끝 카드는 예외(R3).

### E5. 움직임 번짐은 계단 없이 (→ Q4)

### E6. 빛 지나감은 보이게 (→ Q4)

### E7. 정지 1초 금지 (→ Q3)

## R. 잰 값으로 정한 것

### R1. 빈 면은 '더 빔'만 막는다 (→ Q1)
- 샷의 빈 면이 짝 기준 그림보다 **10%p 넘게 더 비면** 안 된다. 도구 값 `empty_diff_vs_anchor`(부호 있는 차, **+면 더 빔**) ≤ +0.10. `measure_motion.py --contact` 또는 `texture/measure_texture.py --shots storyboard/shots.json`이 낸다.
- **더 찬 쪽(−)은 숫자 상한이 없다.** 눈으로 본다: 주인공 시선이 하나, 겹친 층이 3겹 안(바탕 결 · 중간 층 · 주인공, 작은 디테일은 따로), 중간 층(점선·궤적·색면)이 주인공 글자 획 위를 지나지 않음.
- 평평하게 둔 카드·UI 판의 안쪽은 빈 칸이 아니라 **내용**으로 친다. 도구가 카드 안을 빈 칸으로 셌으면 근거 그림을 붙여 그 칸을 빼고 본다.
- **짝 기준 그림을 숫자 맞추려고 바꾸지 않는다.** 맞대기에서 '못하다'가 나면 짝이 아니라 샷을 고친다.

### R2. 소리 마무리 (→ Q8)
- **마스터**는 `scripts/master.py`(믹스 전체에 같은 이득 하나 + 피크 리미터, 목표 −14 LUFS). 경고(끝 코드 2)가 나오면 마스터가 아니라 **믹스**를 고친다. 쓰는 법·경고별 고치는 법은 `references/sound.md` 5장.
- loudnorm(동적 음량 맞춤)은 쓰지 않는다. 선형으로 못 맞추면 동적 모드로 바뀌어 큰 사건 바로 뒤의 작은 사건을 끌어올린다. 그러면 크기 위계가 무너진다.
- **바탕 크기**: LUFS 숫자가 아니라 '효과음이 바로 앞 바탕보다 +8dB 이상인 사건 80% 이상'(E2 ③)이 되는 크기. 맞은 값(마스터 뒤 `--sfx`): 바탕 `bed_dbfs` 중앙값 −20~−28 dBFS, 일반 사건보다 11~16dB 아래.
- **덕킹**: 사건마다 0.25~0.3초 동안 바탕을 **−6~−10dB** 눌렀다가 되돌린다. 음악이 촘촘하면 −10 쪽.

### R3. 끝 카드는 같은 배치 4초까지
- 끝 카드(마지막 샷, 이름·로고 + 맺는 소리)는 같은 배치가 3초를 넘어도 된다. 4초 안. 그 앞 샷들은 E3 그대로.

### R4. 빛 지나감 — 밝은 바탕·흰 요소 위
- 흰 칩·흰 카드 위 흰 빛은 보이지 않는다. 밝은 바탕에서는 둘 중 하나를 쓴다.
  - **따뜻한 색 빛**: 강조색 계열을 옅게(예: 주황 강조면 `#ffd9a8` 안팎), 가장 짙은 곳 불투명도 0.35~0.5.
  - **그림자 쪽 지나감**: 옅은 어두운 띠(검정 8~12%, `multiply`)가 사선으로 한 번 지나감.
- 폭·시간·'360px 사본에서 보여야 함'은 E6 그대로. 끝 카드에만 몰아 넣지 않는다.

### R5. 끝 카드의 느린 흐름은 정지가 아니다
- 끝 카드에는 D5의 아주 느린 흐름(크기 1.00→1.02, 빛 이동)을 둔다. `--pace`가 정지로 잡아도 끝 카드는 Q3 상한에서 뺀다. 비평가는 끝 카드 처음·끝 프레임을 나란히 놓고 흐름이 눈에 보이는지만 본다.
- 끝 카드 밖의 샷은 E7 그대로다. 절제된 UI 화면이 도구 문턱을 넘으려고 화면 전체를 밀지는 않는다.

### R6. 격자가 있는 바탕 결
- 격자·사선이 있는 바탕은 결 세기 범위를 **그레인 몫**(`tex_p50`)으로 보고, 격자 선은 `peak`·`peak360`(2~5)으로 따로 본다. 격자를 포함한 `tex`는 참고로만 적는다.
- 어두운 키네틱 바탕의 추천 값과 측정값은 `references/texture.md` 3장.

### R7. 한글 글자 단위 진폭 — 굵기 700 미만 (→ Q2 겹침)
- 자간 −3~−4%로 조인 한글 낱말에 kx 글자 프리셋을 얹을 때 **회전·크기 진폭은 0~0.5배**(`amp: {rot: 0.5, scale: 0.5}` 이하). `KXP.bounce`는 `rot` 0.3, `squash` 0.3~0.5. `letter_toss_wobble`은 오래 흔들리므로 0.25배.

- 이동 때문에 진폭 0에서도 겹치는 프리셋이 있다: `letter_big_soft_land`(1.3배 크기로 옆에서 다가옴), `letter_spin_flyin_diag`(대각선으로 날아옴). 한글에서는 낱말 묶음 동작(`KXP.group`)으로 쓰거나, 이동 0.25배 + 회전·크기 0.5배로 쓴다.
- 크게 돌고 커지는 움직임이 필요하면 글자 단위 대신 낱말·줄 묶음을 돌린다.

### R8. kx 움직임 프리셋
- **통통 튐**: `KXP.bounce(t0, {drop, bounces, decay, squash, rot, tempo})`. 잰 곡선(`letter_toss_wobble` 솟음·낙하, `letter_stretch_pop` 눌림)으로 만든다. 다른 프리셋의 반쪽을 이어 붙이지 않는다. 착지 프레임 `.landFrames()`를 효과음 시각에 그대로 쓴다(D4).
- **넘침만 따로**: `amp.over`·`amp.rotOver`·`amp.scaleOver`로 넘침만 줄이거나 키운다. 솟는 폭은 `amp.move`. `KXP.overshootOf()`로 표의 넘침 비를 읽어 '목표 비 ÷ 표 비'를 넣는다.
- 이름이 `hold_`로 시작하는 동작은 글자를 숨기지 않는다.
- 쓰는 예와 입력은 `engine/kx/README.md`.

### R9. 데이터 UI 화면의 글자 (→ Q2, T1·T2 보충)
달력·표·대시보드·목록 카드처럼 **칸과 축이 있는 UI 화면**에 쓴다.
- 글자 역할은 셋까지: ① **칸 제목**(일정 이름·수치) ② **축 머리**(요일·날짜·항목 이름) ③ **보조**(시각·단위·설명).
- **축 머리와 보조는 글자 높이 28px 이상, 아니면 뺀다.** 칸 안에 이미 시각이 있으면 행 시각 축은 뺀다. 렌더 프레임에서 잰다(T3).
- 크기 대비: 칸 제목 : 보조 ≥ 2.2. 큰 숫자 머리(날짜) : 작은 머리(요일) ≥ 2.2이거나, 한 줄 한 크기로 묶는다.
- **가로 1920 주간 달력은 요일 5칸 이하.** 7칸이면 칸이 좁아 보조 28px과 제목:보조 2.2를 함께 채울 수 없다. 7칸이 꼭 필요하면 칩에는 제목만 남기고 보조(시각)를 뺀다(`ui.calendar_week` `labels: false`). `ui.calendar_week` 기본값이 이 줄을 따른다(요일 5개, 제목 82px·시각 39px → 렌더 글자 높이 약 72~75:31).
- **달력 시그니처 칩**: `pop: true, hold_scale: 1.1~1.15, fill: true` — 채운 칩 하나가 그 화면의 강조 하나다. 나머지 칩은 회색 띠, 오늘 표시는 `ring`(무채색 테두리 — 강조로 세지 않음). 카메라로 크게 밀 때는 `draw_scale`을 그 배율 이상으로 준다.
- 강조는 화면에 하나(T1) — 보통 강조색 칸 하나.
- **상태 표시**(오늘·선택·진행 중)는 채우지 않은 테두리 또는 밑줄, 무채색, 본문과 같은 굵기면 강조로 세지 않는다. 채운 원·강조색·더 굵게는 강조 하나로 센다.
- `review/type_spec.md`에 데이터 UI 줄을 더한다: 역할 3개 크기(px), 28px 미만 글자 수(0이어야 한다), 상태 표시 모양.

### R10. 굵은 한글 키네틱은 낱말 묶음 (→ Q2 겹침·자간)
- **굵기 700 이상 한글은 글자 단위로 떨어뜨리거나 튀기지 않는다.** 낱말(어절) 하나가 한 덩어리로 움직인다. kx 엔진은 `KXP.bounceWords`를 쓴다(`engine/kx/README.md`).
- 글자 단위 움직임은 **강조 낱말 하나에만** 둔다(`focus`). 그때도 눌림(squash) ≤ 0.2, 회전 0, 세로 번짐 길이 ≤ 글자 높이의 25%.
- **겹침을 자간으로 풀지 않는다.** 자간은 A4 값 그대로 두고, 겹치면 진폭을 줄이거나 낱말 묶음으로 바꾼다.
- **보이지 않는 마스크가 글자를 조각내면 안 된다.** 글자가 마스크 선을 지나 들어오면 그 선을 화면에 보이는 것(바닥선·판 가장자리)과 맞추거나, 글자가 화면 밖에서 통째로 들어오게 한다(`drop: "offscreen"`).
- 왜: 굵은 한글은 획이 촘촘해 0.5배 진폭에서도 이웃 글자에 붙는다. 자간을 벌려 풀면 '한글 +자간 금지'에 걸리고, 세로 번짐은 자모를 늘여 보이게 한다.

### R11. 짝 기준 그림보다 작게 찍지 않는다 (→ 맞대기)
- 샷의 **주인공 높이가 짝 기준 그림 주인공 높이의 0.7배 이상**이어야 한다. **더 작은 쪽만 막는다.** 더 크게(더 가까이) 찍는 것은 숫자로 막지 않는다.
- `storyboard/shots.json` 샷마다 `anchor_scale`에 세 가지를 적는다: 짝의 주인공 높이, 이 샷의 목표 높이, 잴 프레임(대표 프레임 + 누름·착지 같은 동작 프레임). 꼴은 아래로 정해 두고, 높이는 `pair_board.py --scale`의 `scale.json`과 같은 **비**(주인공 높이 ÷ 화면 높이, 0~1 — 0.24 = 화면 높이의 24%)로 적는다. 퍼센트 숫자(24)로 적지 않는다.
  ```json
  "anchor_scale": {
    "anchor_pct": 0.24,
    "target_pct": 0.30,
    "frames": [92, 118],
    "measured": [
      {"frame": 118, "pct": 0.104, "height_ratio": 0.43, "by": "tool"},
      {"frame": 118, "pct": 0.20, "height_ratio": 0.83, "by": "eye", "why": "도구가 오늘 칸 테두리를 주인공으로 잡음 — 달력 판 높이를 눈으로 잼"}
    ]
  }
  ```
  - `anchor_pct` = `scale.json` `pairs[].anchor_est.pct`(짝 기준 그림의 주인공). `target_pct` ≥ `anchor_pct × 0.7`.
  - `frames` = `pair_board.py --pair <프레임>=<anchor>`에 그대로 넣을 프레임.
  - `measured`(잰 뒤에 더함): 프레임마다 `scale.json` `pairs[]`의 `frame`, `result.pct` → `pct`, `height_ratio`를 그대로 옮기고 `by: "tool"`. 도구가 주인공을 잘못 잡아 눈으로 다시 쟀으면 그 줄은 `by: "eye"` + `why`(근거 그림은 `review/pairs/`).
- 키프레임 관문과 비평 전 점검에서 `critic/tools/pair_board.py --scale`로 짝과 나란히 놓고 높이 비(이번 ÷ 짝, `height_ratio`)를 본다. 0.7 아래면 샷을 고친다(가까이 밀어 들어가기·주인공 키우기). 짝은 바꾸지 않는다(R1).
- 도구 값은 **추정**이다. 밝은 바탕 위 흰 입력창·카드처럼 바탕과 색 차가 작은 판은 상자로 안 잡혀 커서·아바타를 주인공으로 잡고, 조각난 물체는 조각 하나만 잡는다. 그럴 때는 눈으로 잰 값을 근거 그림과 함께 적는다.
- 왜: 짝이 입력창을 크게 당긴 화면인데 결과가 넓은 판 가운데 작은 아이콘이면, 비평가는 같은 유형이라도 '못하다'로 본다.

### R12. 효과음 등급 순서와 사건 프레임 (→ Q8 조건 ④)
- 등급별 크기(사건 봉우리, `--sfx`)의 중앙값이 **detail < normal < first·signature** 순서여야 한다.
  - detail 중앙값은 normal 중앙값보다 **2dB 이상 작게**.
  - normal과 first·signature의 차는 E2 ②(+4dB) 그대로.
- `scripts/master.py`도 등급 순서가 뒤집히면 경고한다(끝 코드 2). 경고가 나오면 믹스를 고친다.
- 부품 `events()`는 `normal`·`detail`만 낸다. 머릿사건 후보에는 `hint: "first"` 또는 `"signature"`가 붙는다. 영상 전체의 first·signature는 만드는 쪽이 `KC.retier`로 하나씩 고른다.
- 사건 프레임은 부품 `events()`의 `onset`(움직임 시작)과 `land`(닿음·멈춤)에서 고른다.
  - 휙·쓸림 소리 → `onset`
  - 착지·누름·딸깍 → `land`
- 왜: 작은 튐·반짝이 낱말 착지보다 크면 귀로 위계가 뒤집혀 들린다. 부품의 '다 들어온' 프레임에 소리를 두면 렌더와 1~3프레임 어긋난다.

### R13. 움직임 번짐 모양 (→ Q4·E5, 돌출 금지)
- 번짐은 **움직임 방향 가운데 기준**(앞뒤로 반씩)으로 놓는다. 가장 빠를 때 길이가 물체 짧은 변의 **50% 이하**.
- **글자가 실린 것은 글자 높이 × 0.25 이하**(v0.6.7, '바코드' 막기). 짧은 변 50%는 카드 크기 기준이라 글자보다 훨씬 길 수 있고, 그러면 번짐 방향 획(세로 번짐이면 가로획)이 옅어져 가로지르는 획만 줄무늬로 남는다(상자 흐림의 성질 — float 판에서도 같음). 낱말(`KCB2.drawWord`)은 이 상한이 기본이다(글자 높이 = 0.8em). 글자가 실린 그림·층(`KCB6.smearImage`·`KCB3.smearDraw`)은 도우미 기본이 상한 없음 그대로이고, **부르는 쪽이 `max: KC.smearMax(그 그림의 가장 작은 글자 px)`를 넘긴다**. 화면 크기 전환(아래 예외)은 이 상한도 두지 않는다.
- 사본 간격이 2px 넘게 벌어져 계단이 보이면 사본 수를 늘리거나 길이를 줄인다(E5).
- 정지 화면 한 장에서 한쪽으로만 진한 꼬리가 붙어 **돌출 그림자처럼 보이면 안 된다**(돌출 그림자 금지는 T1).
- 부품 밖에서 번짐을 직접 그리면 공용 도우미를 쓴다: `KCB6.smearImage`(그림 하나)·`KCB3.smearDraw`(장면 층)·`KCB2.drawWord`(낱말)·`KC.smearFn`(그리는 콜백 — 여러 그림을 묶어 한 번 그린 뒤 평균, v0.6.7). 사본을 알파 1−(1−a)^(1/K)로 차례로 덮어 그리지 않는다(꼬리까지 진한 돌출 그림자). 회전 번짐은 `KCB15.spin`·`KCB17.spinDraw`(`components/README.md` 도구 표). kx 엔진 기본(`motionBlur {center: "space", cap: 0.5}`)은 이미 이 규칙을 따른다.
- 예외 둘(계단 금지는 예외 없이 그대로):
  - **화면 전체가 움직이는 전환**(휙 넘김·줌 통과): 길이 50% 상한도, 글자 높이 × 0.25 상한도 두지 않는다(글자 기준으로 자르면 한 프레임 177px 이동에 번짐 9px — 끊기고 색 갈라짐 테두리가 드러남, v0.6.7 비평). 번짐이 곧 전환이다. 푸는 것은 길이 상한뿐이다 — 가운데 기준(한쪽 진한 꼬리·돌출 금지)과 계단 금지는 지킨다. 글자가 주인공인 줌 통과는 가장 빠른 프레임에서 번짐 폭이 획 폭의 2배를 넘으면 회색 판처럼 보인다 → 장면에서 `shutter`를 낮춘다(`transition.zoom_through` README 한계).
  - **의도한 잔상**(글리치 사본, 속도 잔상처럼 일부러 끊긴 사본을 보이는 연출): 효과로 둔다. 그런 부품은 README에 'R13 예외 — 의도한 잔상'이라고 적혀 있다. 움직임 번짐 대신 쓰지 않는다.

## T. 타이포

### T1. 강조는 화면마다 정확히 하나 (→ Q2)
- 글이 있는 화면은 **강조가 정확히 1개**다. 0개도 위반, 2개 이상도 위반.
- 강조로 치는 것(하나만 고른다):
  1. **크기**: 주인공 낱말이 곁 낱말의 3.5배 이상(키네틱). 크기 강조를 고르면 그 낱말은 다른 강조를 갖지 않는다.
  2. **굵기**: 같은 가족 안 300 이상 차이(400 ↔ 800). 300 차이 미만은 강조로 안 읽힌다.
  3. **색 하나**: 강조색 한 가지, 한 낱말(구)에만.
  4. **세리프 전환**: 산세리프 줄 안 한 낱말만 세리프로(`display_serif` 가볍게 또는 `serif_bold` 같은 무게). 세리프 낱말에 강조색을 더해도 한 강조로 센다.
- 강조로 안 치는 것(쓰면 강조를 하나 더 쓴 것): 밑줄, 돌출(extrude) 그림자, 외곽선, 그라데이션 글자, 글자 옆 장식 막대. **돌출 그림자는 어디에도 쓰지 않는다**(A4 금지 1을 넓힘).
- 굵게 + 색 + 밑줄 + 그림자처럼 강조를 겹치지 않는다. 크기를 키우는 강조는 키네틱 주인공 낱말에서만.
- 예외: 로고·이름 한 낱말만 있는 화면은 그 낱말이 곧 주인공이다(강조 0개 허용). 그 아래 부제가 있으면 다시 T1을 따른다.
- 예: "가계부 정리를 **3분** 만에" → 강조는 '3분' 크기(3.5배) **또는** '가계부' 주황 중 **하나**. 둘 다 쓰지 않는다.

### T2. 격자·묶음은 칸이 단위, 문장은 한 줄에서만 (→ Q2)
- **문장(이어 읽히는 말)은 한 줄(또는 한 덩어리)에서만** 보여 준다. 문장을 격자 칸에 펼치지 않는다.
- **격자·묶음 칸**은 서로 독립된 단위다. 칸마다:
  - 낱말(구) 하나 + 역할 하나. 칸 안 처리(서체·색·효과의 조합)는 2가지 이하(예: 글자 + 작은 라벨 / 글자 + 색).
  - 칸 안에도 크기 위계가 있다: 칸 주인공 : 칸 라벨 ≥ 3.5. 라벨은 대문자 높이 28px 이상이거나 아예 없다(21~23px 라벨은 폰에서 점이 된다).
- 격자 전체는:
  - **역할 2~3개**, **크기 2~3단계**(큰·중간·작은 라벨). 칸마다 서체를 다 바꾸지 않는다. 잘 된 격자도 9칸이 3~4개 결로 묶인다.
  - **강조색 칸은 1~2개**, 나머지는 무채색.
  - **같은 낱말 반복은 2번까지**. 같은 말을 낱자로 쪼개 칸을 채우지 않는다.
  - 행마다 기준선(칸 아래끝)이 한 줄로 맞는다(±4px).
  - 칸을 채울 말은 요청 안에서만(C2·D2). 말이 모자라면 칸 수를 줄이거나(6칸·4칸), 글 없는 칸은 1개까지(재생 단추처럼 뜻 있는 그림).
- 비평 Q2의 '처리 2가지'는 **문장 한 줄** 또는 **칸 하나** 단위로 센다.
- **데이터 UI 화면**(달력·표·대시보드)은 R9를 따른다.

### T3. 크기 대비는 재서 적는다 (만드는 쪽 점검)
- 키프레임 승인 전과 비평 전에 `review/type_spec.md` 표를 채운다(샷마다 대표 프레임 1장). 표 꼴과 재는 법은 `references/typography.md` 3장.
- 크기는 코드의 font-size가 아니라 **렌더 프레임에서 잰 대문자(한글은 글자) 높이**다.
- 통과선: 키네틱 주인공:곁 ≥ 3.5, UI 제목:본문 ≥ 2.2, 크기 단계 ≤ 3, 강조 정확히 1, 칸·줄 안 처리 ≤ 2, 같은 낱말 반복 ≤ 2. 데이터 UI는 R9 줄도. 하나라도 못 채우면 그 샷을 고친 뒤 넘어간다.
- 시그니처 샷은 **정지 화면 한 장으로도** 주인공 낱말이 보여야 한다(크기 강조면 3.5배, 아니면 화면 폭 60% 이상인 한 줄 안에서 강조 하나).
- `review/type_spec.md`는 만든 쪽의 점검 기록이라 비평가에게 주지 않는다.

### T4. 9점으로 가려면 (선택)
- 낱말마다 성격을 준다: 한 화면의 크기 강조 낱말(키네틱) + 다른 화면의 세리프 전환 + 큰 숫자처럼, **화면마다 다른 강조 하나**를 돌려 쓴다.
- 글자 단위 움직임은 강조 낱말에만 더 크게(곁 낱말은 한 덩어리로 조용히). 회전 중심이 맞는 글자 단위 움직임, 굵기 축을 시간에 따라 바꾸기(kx 엔진에서 인스턴스 여러 개를 뽑아 바꿔 그림).
